# Frontend engineering

- Accessibility and responsive behavior are part of completion.
- Use semantic HTML, keyboard support, labels, focus management, contrast, and meaningful error feedback.
- Design loading, empty, error, offline/retry, and partial-success states.
- Keep navigable/filter/search/pagination state in the URL when appropriate.
- Do not duplicate server state into global client stores without need.
- Validate external data at runtime.
- Prefer composition and explicit state ownership over giant components and boolean prop matrices.
- Respect the existing design system and styling approach before adding libraries.
- Test user-visible behavior and critical journeys, not internal component details.
- Consider browser compatibility, performance budgets, image/font loading, and public SEO where applicable.

# Architecture decisions

An ADR should contain status, context, decision drivers, considered options, decision, consequences, risks, and follow-up.

- Record decisions that constrain future work, not every implementation detail.
- Cite evidence and rejected alternatives fairly.
- Make compatibility, migration, operational, security, and rollback consequences explicit.
- Never silently rewrite accepted history. Supersede with a new ADR and links.
- Architecture decisions require manual approval before becoming accepted.

# Dart engineering

- Use sound null safety and explicit domain types.
- Keep Futures, Streams, cancellation/disposal, and error propagation deliberate.
- Prefer composition and small APIs over deep inheritance.
- Avoid dynamic unless an external boundary forces it; validate decoded data.
- Respect `dart format`, `dart analyze`, project lints, and tests.
- Separate pure business logic from platform/UI code for testability.
